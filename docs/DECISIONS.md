# Design decisions

Each decision lists what was chosen, what else was considered, and why. Measured evidence is in `docs/MODEL_CARD.md`
(regenerated from artifacts by `python -m ssa.cli report`); the section to read is named in each row.

| # | Decision | Alternatives considered | Why | Evidence |
|---|---|---|---|---|
| 1 | Score only students still enrolled at each checkpoint; evaluate on a later presentation (temporal split) | random split over all students | v4's 0.90 AUC came from scoring students who had already left; a random split leaks the future | Model card: data and population; `docs/AUDIT_FIXES.md` |
| 2 | Four checkpoints (weeks ~6, 9, 15, 22), one model bundle each | one model at one week | advisors need warnings early, and accuracy and base rates change through the course | Model card: early warning across the course |
| 3 | Gradient-boosted trees (XGBoost), calibrated, TreeSHAP explanations | logistic regression (kept as baseline), neural nets | best ranking on tabular features, exact per-student explanations, fast on CPU | Model card: withdrawal model, ablations |
| 4 | Sensitive attributes excluded from the model; used only for the fairness audit and filters | include them for accuracy | they add essentially nothing to accuracy and would make the scores harder to defend | Model card: ablation "full_with_sensitive", fairness audit |
| 5 | Learned prioritisation with a one-standard-error rule | the v4 hand formula; best grid point only | weights fitted for precision at advisor capacity; the 1-SE rule prefers a blend that uses actionable signals when it is statistically as good | Model card: prioritisation |
| 6 | Hybrid retrieval: supervised behavioural kNN + BM25 over descriptors + dense narrative embeddings, weighted RRF | dense-only RAG; keyword-only | profiles are numeric, so behavioural similarity carries student-to-student search; dense helps typed free-text search; RRF needs no score calibration across channels | Model card: historical-case retrieval, typed search |
| 7 | One document per enrolment, no chunking; 6 precedent stories in the context, outcome mix over the 50 nearest | chunking narratives; one top-K for both | a case is one short record; small K keeps prompts readable, larger K gives steadier outcome estimates | Model card: retrieval strategy (top-K sensitivity) |
| 8 | Vector database: LanceDB, embedded, exact search with metadata pre-filter | NumPy arrays (kept as `VECTOR_STORE=numpy`), Chroma, Qdrant server, FAISS | no extra service; filters pushed down so they never drop true neighbours; exact results at ~25k vectors per checkpoint; scales to ANN indexes if the corpus grows | `docs/DESIGN.md` retrieval; `tests/test_vector_store.py` |
| 9 | Embedding model: all-MiniLM-L6-v2 | all-mpnet-base-v2, bge-small-en-v1.5, e5-small-v2, gte-small | compared on the same narratives for typed-search precision, precedent quality, encoding speed, latency and index size | Model card: embedding model evaluation |
| 10 | Claude in three tiers: Haiku for parsing and rewrites, Sonnet for agents, copilot and synthesis, Opus as judge | one model for everything; the judge equal to the generator | the same features were run on each tier: Haiku parses as well as larger models for a fraction of the cost; Sonnet writes the most faithful syntheses; a separate, stronger judge avoids self-grading | Model card: LLM selection |
| 11 | The LLM narrates and selects; code decides facts, scores, eligibility and priority | LLM free text for priority (v4) | every LLM output is checked in code and has a deterministic fallback, so the system works with the LLM off | `ssa/agents/guardrails.py`, `tests/test_workflow.py` |
| 12 | Multi-agent workflow as a LangGraph state graph; reference orchestrator kept | plain Python only; LangChain agents; LlamaIndex | the graph makes the control flow explicit and renderable; nodes call our agents so guardrails, cache and cost ledger stay; LangChain/LlamaIndex wrappers would replace tuned, measured components | `docs/AGENT_GRAPH.md`, `tests/test_graph.py` |
| 13 | Copilot as tool use over 8 read-only tools, streamed over server-sent events | free-form RAG chat | answers come from the same computed functions as the console; tool calls are shown; streaming makes waits visible | `ssa/agents/copilot.py`, `/api/copilot/stream` |
| 14 | Evaluation in layers: code checks, LLM judge with anchored rubrics and order-swapped A/B, DeepEval, RAGAS, human labels | a single metric | each layer catches what another misses; the judge is checked against blind human ratings | Model card: AI features, RAGAS; console: Model quality > Human review |
| 15 | RAGAS in its own environment | install with the service | RAGAS pulls the LangChain stack and forced upgrades that broke pinned dependencies | `requirements-ragas.txt`, `scripts/ragas_eval.py` |
| 16 | One FastAPI microservice serving the React console; jobs and rate limits shareable through SQLite | separate frontend server; Redis from day one | simplest deployable unit; scales to several workers per host, then to a queue and gateway limits | `docs/DEPLOYMENT.md` |
| 17 | Course-clock console design with functional colour | generic dashboard | every number is "as of" a point in the course; colour carries meaning (tier, AI-drafted, current point) | `frontend/DESIGN.md` |
